## 기록

### 2026-09-28 ① 데이터·시스템 — 실전 쪽에 ADR 조건이 빠져 있었다
- **내가 말한 것**: 6팀 매수 계획을 만들고 "오늘 밤 관심 5종목"이라고 보고했다. 그중 ZBRA 가 있었다.
- **실제 결과**: ZBRA 의 ADR 은 3.0% 로 전략 기준(4%) 미달이었다. 백테스트에는 `ADR ≥ 4` 조건이 있었는데 실전 매수 계획에는 없었다.
  차트를 읽다가 발견했다. 고친 뒤 관심 종목은 4개다.
- **왜 틀렸나**: 같은 조건을 두 군데(백테스트의 후보 필터, 실전의 막는 사유)에 따로 썼다. 백테스트에는 숫자 `4` 를 직접 적었고 실전에는 적지 않았다.
  6팀 후보에는 2팀 통과 종목뿐 아니라 3팀 추적 종목도 들어오는데, 3팀 종목은 ADR 조건을 거치지 않는다는 걸 확인하지 않았다.
- **앞으로의 규칙**: 조건은 `config/rules.json` 한 곳에 두고 백테스트와 실전이 같은 키를 읽는다(`risk.minAdrPct`).
  새 조건을 넣을 때 `grep` 으로 백테스트와 실전 양쪽에서 읽는지 확인한다.

### 2026-09-28 ② 데이터·시스템 — 한투 API 신청 절차를 기억으로 안내했다
- **내가 말한 것**: "KIS Developers 에서 회원가입 → 로그인 → API 신청", "한투 홈페이지 ID 가 곧 KIS Developers ID", 신청 주소로 `OpenAPI.jsp` 를 줬다.
- **실제 결과**: 셋 다 틀렸다. 회원가입 버튼은 없고, KIS Developers ID 는 신청 과정에서 새로 만들어지며, 준 주소는 옛 API 페이지였다.
  ID 로그인은 조회 전용이라 신청이 안 되는 것도 몰랐다. 사용자가 여러 번 막혔다.
- **왜 틀렸나**: 공식 페이지를 열어보지 않고 일반적인 가입 흐름을 가정했다. 첫 안내가 막혔을 때도 페이지를 확인하지 않고 다른 추측을 냈다.
- **앞으로의 규칙**: 외부 서비스의 절차를 안내할 때는 먼저 그 페이지를 가져와(WebFetch) 버튼 이름·주소·로그인 방식을 확인한 뒤 말한다.
  확인하지 못한 단계는 "확인하지 못했다"고 표시한다.

### 2026-09-28 ③ 차트 소견 — 첫 9건 (2026-10-04 에 채점, 5세션 경과)
- **내가 말한 것**: FEIM·SIG·HNGE·NUTX·DELL keep · ZBRA·LITE·PANW hold · SIMO drop. 내용은 `state/breakout-log.json`.
- **실제 결과**: 9건 중 **5건 틀림**(④ ⑤ 에 사유별로 적었다) · 3건 맞음(HNGE keep 은 9/30 돌파 · SIMO drop·ZBRA hold 는 미돌파) · 1건 미결(SIG keep, 10세션 창까지 5세션 남음).

### 2026-10-04 ④ 차트 소견 — hold 라고 쓴 2건이 돌파하고 더 올랐다 (LITE·PANW)
- **내가 말한 것**: LITE `hold` — "피벗까지 8.3%(1.4 ADR)로 아직 멀다. 범위는 옆으로 가지만 좁아지지는 않았다."
  PANW `hold` — "피벗 398.88 바로 아래 395~399 에서 두 번째로 밀렸다. 봉이 좁아지는 모습은 아니다."
- **실제 결과**: LITE 10-01 돌파(거래량 7.55M, 5세션 중 최대), 소견 뒤 +15.3% · 최고 +15.9%. PANW 10-02 돌파, +7.6% · 최고 +9.3%.
  둘 다 등급 A 였고 둘 다 소견과 반대로 갔다.
- **왜 틀렸나**: LITE 는 ADR 5.96% 였다. 1.4 ADR 은 하루 반 치 거리인데 "8.3%"라는 백분율 숫자를 보고 멀다고 썼다 —
  `CLAUDE.md` 에 이미 "피벗까지의 거리는 ADR 배수로 잰다"고 적혀 있고 소견문에 ADR 배수까지 괄호로 써 놓고도 % 로 판단했다.
  규칙에서 "far"(1~1.5 ADR)는 **오늘 사지 않는다**는 뜻인데 **돌파하지 않을 것**으로 바꿔 읽었다.
  PANW 은 9/25 종가 위치 7%(저가 근처)를 거부 신호로 썼지만 바로 다음 세션 9/28 에 370.61 에 열려 392.09(종가 위치 91%)로 되돌렸다.
  약한 종가 한 봉은 다음 봉에서 지워진다. 그리고 두 달 330~399 는 공식 기준 베이스 범위(2주~2개월) 안인데 "넓은 범위"를 감점 사유로 삼았다 — 깊이는 `gradeSetup` 이 재는 검사다.
- **앞으로의 규칙**: 피벗까지의 거리는 `distToPivotAdr` 만 인용하고 %는 쓰지 않는다. 1.5 ADR 이내는 `hold` 사유로 쓰지 않는다.
  마지막 봉 하나의 종가 위치로 `hold`/`drop` 을 쓰지 않는다 — 최근 10봉 중 몇 봉이 아래쪽에서 끝났는지만 적는다.
  베이스 길이·깊이는 등급에 이미 반영되어 있으므로 소견에서 다시 감점하지 않는다.

### 2026-10-04 ⑤ 차트 소견 — keep 라고 쓴 3건이 −1 ADR 넘게 내려갔다 (DELL·NUTX·FEIM)
- **내가 말한 것**: 셋 다 `keep` — "거래량이 줄며 되돌렸고 10일선 위에서 멈췄다"(DELL) · "20일선에서 두 번 멈췄다"(NUTX) ·
  "11봉이 83~89.8 에서 옆으로, 거래량 줄었다"(FEIM).
- **실제 결과**: 5세션 안에 DELL −1.24 ADR · NUTX −1.15 ADR · FEIM −1.35 ADR 까지 내려갔고 셋 다 미돌파.
  소견 뒤 수익률 DELL −0.1% · NUTX −1.6% · FEIM −2.7%.
- **왜 틀렸나**: 셋 모두 소견 직전 봉이 그 구간에서 가장 큰 양봉이었다(DELL 9/25 +5.0% 종가 위치 66% · NUTX 9/25 +7.6% 89% · FEIM 9/25 +4.6% 73%).
  나는 그 봉을 "베이스 안에서 10일선 위로 복귀"로 읽었지만, 그 가격이 기준가가 되어 다음 봉부터는 되돌림이 전부 마이너스로 잡혔다.
  NUTX 소견문에는 "직전 봉이 이미 큰 양봉이라 다음 날 진입은 하루 늦은 자리다"라고 직접 써 놓고도 결론은 `keep` 으로 냈다 — 본 것과 결론이 어긋났다.
  FEIM 은 바로 다음 세션에 87.45 에 열려 82.49(종가 위치 13%)로 끝났고 이후 5세션 동안 89.76 을 한 번도 건드리지 못했다.
- **앞으로의 규칙**: 직전 봉이 최근 10봉 중 최대 상승폭이면 소견에 **그 사실과 당일 종가 기준 거리**를 함께 적고,
  그 봉의 복귀를 베이스 근거로 쓰지 않는다. 소견문 안에 걸리는 점을 적었으면 결론은 `keep` 이 될 수 없다 — 쓴 것과 결론이 어긋나면 결론을 바꾼다.
