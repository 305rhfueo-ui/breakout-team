# 주간 리뷰

사용자가 `리뷰`, `주간 리뷰`, `모의투자 성적`, `/review` 라고 하면 실행한다.

REPO: `~/AI/breakout-team`

## 절차

0. **`docs/CLAUDE-NOTES.md` 와 `docs/STRATEGY-LOG.md` 를 먼저 읽는다.**

1. 숫자를 뽑는다.
   ```bash
   cd "<REPO>" && node scripts/paper-review.js
   ```
   터미널에 표가 나오고 같은 내용이 `docs/STRATEGY-LOG.md` 뒤에 붙는다.

2. 사용자에게 보고한다. 순서:
   - 끝난 거래 수, 승률, 평균 R, 손익비, 누적(계좌 대비 %), 최대 낙폭
   - 실제 규칙 vs 그림자 장부 셋(20일선 트레일 · 다음 날 시가 진입 · 등급 C)
   - 구간별 표에서 **표본 10건 이상인 줄만** 짚는다
   - Claude 차트 소견 대조표

3. **오답노트를 쓴다.** `docs/CLAUDE-NOTES.md` 의 채점 대기 항목에 결과를 채운다. 형식은 다섯 줄 고정:
   날짜 · 내가 말한 것 · 실제 결과 · 왜 틀렸나 · 앞으로의 규칙.
   - `keep` 이라고 썼는데 10세션 안에 피벗을 못 넘었거나 −1 ADR 이상 내려갔으면 틀린 것이다.
   - `hold`/`drop` 이라고 썼는데 피벗을 넘고 더 올랐으면 틀린 것이다.
   - "왜 틀렸나"는 그날의 차트 PNG 를 다시 그려(`render-charts.js --tickers=… --date=…` 는 그날 봉을 못 되돌리니
     지금 차트에서 그 시점을 찾아) 무엇을 놓쳤는지 구체적으로 쓴다. 모르면 "모른다"고 쓴다.
   - "앞으로의 규칙"은 행동으로 확인할 수 있는 문장만. 다짐은 쓰지 않는다.

4. 규칙 변경 제안.
   - **끝난 거래가 30건 미만이면 제안하지 않는다.** "관찰 단계"라고 말하고 끝낸다.
   - 30건 이상이면 **하나만** 제안한다. 근거 숫자(표본 수 포함)와 함께.
   - 제안은 곧바로 적용하지 않는다. `config/rules.json` 의 `shadow` 에 넣어 2주 동안 그림자로 돌린 뒤,
     그림자가 실제보다 나았을 때만 사용자 승인을 받아 바꾼다.
   - 바꿀 때는 `version` 을 올리고 `docs/STRATEGY-LOG.md` 에 전후 숫자를 남긴다.

## 규칙

- **숫자를 바꾸지 마라.** 스크립트가 낸 값을 그대로 전달한다.
- 몇 건 졌다고 규칙을 뒤집자고 하지 마라. 쿨라매기 방식은 승률 30%대가 정상이고 큰 이익 몇 건이 전체를 만든다.
- 체결은 자체 장부의 계산이다. 실제 매매는 슬리피지·체결 실패가 더 있다는 점을 매번 밝힌다.
- 수익을 약속하지 마라.
