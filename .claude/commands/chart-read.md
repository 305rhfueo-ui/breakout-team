# 차트 읽기 (Claude 비전)

사용자가 `차트 읽어줘`, `차트 분석`, `/chart-read` 라고 하면 실행한다.

REPO: `~/AI/breakout-team`

## 왜 이건 되고 팀 에이전트는 안 되나

워크플로 안의 팀 에이전트(2·4·5팀·실장)는 숫자 텍스트만 받는다. 봉도 그림도 없다 — 그래서 차트 모양을 말하면 지어낸 것이다.
이 커맨드는 **Claude Code 세션이 렌더된 PNG 를 Read 도구로 직접 본다.** 본 것만 말한다.

## 절차

0. **`docs/CLAUDE-NOTES.md` 를 먼저 읽는다.** 지난 오답에서 나온 규칙을 이번에 적용한다.

1. 차트를 그린다.
   ```bash
   cd "<REPO>" && node scripts/render-charts.js              # 6팀 관심·피벗 근처·이미 돌파·차트확인
   cd "<REPO>" && node scripts/render-charts.js --watch-only # 6팀 관심 종목만
   cd "<REPO>" && node scripts/render-charts.js --tickers=ZS,MRNA
   ```
   출력 마지막 줄의 `dir` 아래에 `{TICKER}-3m.png`, `{TICKER}-6m.png` 가 생긴다 (저장소 밖 캐시 폴더).
   주황 점선 = 피벗, 빨강 점선 = 예비 손절.

2. 숫자 사이드카 `state/chart-views/{날짜}.json` 을 읽는다. **가격·거래량·종가 위치는 여기서 인용한다.**
   그림에서 눈으로 읽은 가격은 ±1% 오차가 있다.

3. 종목마다 **3개월 그림의 최근 10봉을 먼저**, 그다음 6개월 그림을 본다. 아래 다섯 가지를 본 그대로 적는다.
   - 추세 구조 — 고점·저점이 높아지는가, 이동평균선과의 위치
   - 베이스 — 몇 봉 동안 어느 가격대에 있었나, 봉이 좁아졌나 넓은가
   - 피벗 부근 — 윗꼬리가 몇 번 나왔나, 종가가 봉의 어디서 끝났나
   - 거래량 — 어느 봉에서 컸나, 최근에 줄었나
   - 걸리는 점 — 갭, 넓은 음봉, 얇은 거래량, 직전 큰 양봉 등

4. 결론은 셋 중 하나.
   - `keep` 계획 유지 — 숫자가 잡은 베이스가 그림에서도 보인다
   - `hold` 보류 — 아직 피벗에서 멀거나, 그림이 숫자와 다르다
   - `drop` 제외 — 베이스가 아니다(넓은 봉 하락, 갭 하락 등)

5. 기록한다.
   ```bash
   cd "<REPO>" && node scripts/mark-breakout.js --by=claude --ticker=FEIM --verdict=keep --note="본 것을 문장으로"
   ```
   대시보드 6팀 탭과 리서치룸 서준 카드에 "🤖 클로드 차트 소견"으로 바로 표시된다.

6. 사용자에게 종목별로 보고하고, 마지막에 `node scripts/update-github.js "차트 소견 N건"` 으로 올린다.

## 규칙

- **본 것만 쓴다.** "매집", "세력", "에너지 응축", "곧 터진다" 같은 해석을 붙이지 마라. 봉·선·막대에서 보이는 것과 사이드카의 숫자만.
- **예측하지 마라.** 소견은 "지금 그림이 이렇다"이지 "오를 것이다"가 아니다.
- **소견은 6팀의 매매를 바꾸지 않는다.** 6팀은 숫자 규칙으로만 움직인다. `drop` 이라고 써도 밤에 조건이 맞으면 산다.
  사용자가 빼라고 하면 그때 관심 목록에서 뺀다. (소견이 실제로 성적을 가르는지는 `/review` 에서 대조한다.)
- 소견은 나중에 실제 결과와 대조해 채점한다. 틀린 것은 `docs/CLAUDE-NOTES.md` 에 남는다.
- 최종 판단은 사용자다. "사세요"가 아니라 "차트에서 이것을 확인하세요"로 말한다.
